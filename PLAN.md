# Private video platform: build plan

A private YouTube with a public **viewer site** and a login-only **creator studio**.

**Stack (fixed):** Next.js App Router · Tailwind · Supabase (auth + database) · ImageKit (all media: storage, adaptive streaming, thumbnails, player).

**Hard rule:** we build no video infrastructure. That means no ffmpeg, no transcoding, no HLS server, no CDN config and no analytics events of our own. ImageKit URLs provide the video versions and thumbnails, and `@imagekit/video-player` provides playback and viewer analytics. Our code is only the product around them.

**In scope:** home feed, watch page (chapters, preview thumbnails when hovering the seek bar, floating mini-player, up-next sidebar), playlists, dark premium UI, studio upload with progress, video editing (title, description, thumbnail frame, playlists), publish/unpublish, a members-only flag.
**Out of scope:** comments, likes, search, subscriptions, and anything else not listed.

## Player API (checked against the package itself, not memory)

Context7 isn't connected in this session, so I read the player's API from the published package's own type files (`dist/index.d.ts`, `dist/react/index.d.ts`) and from the ImageKit docs you pasted.

- **Version:** pin **`@imagekit/video-player@1.0.0-beta.5`**. It's published under the `beta` tag. The `latest` tag (beta.4) doesn't have the `analytics` option.
- **React:** `IKVideoPlayer` takes `ikOptions` (required), `videoJsOptions`, and either `source` or `playlist`. A ref exposes `getPlayer()`.
- **What we'll use:**
  - `ikOptions`: `imagekitId: 'uequzrrfb'`, `abs: { protocol: 'hls', sr: [360, 480, 720, 1080] }`, `seekThumbnails: true` (the default), `floatingWhenNotVisible: 'right'`, `signerFn`, `analytics: { enabled: true, userId?, customDimensions? }`.
  - `source`: `src`, `chapters: true` (chapters generated by ImageKit's AI), `poster: { src }`, `info: { title, description }`.
- **Problems found in the React wrapper. We'll write our own client wrapper to handle them:**
  1. **No `'use client'` marker, and Video.js needs the browser.** We load it through our own client component with `next/dynamic({ ssr: false })`.
  2. **It only rebuilds the player when `ikOptions` or `videoJsOptions` change, not `source`.** Moving from one video to another would keep playing the old one. Fix: remount with `key={video.id}`.
  3. **`videoJsOptions` defaults to a fresh `{}` on every render,** which rebuilds the player each time. We always pass memoized objects.
  4. **React Strict Mode in development runs effects twice,** and the Video.js teardown removes the `<video>` element. We check for this in M2. If it breaks the player, the fix is a local wrapper that creates the `<video>` element itself.

## How private media works (the members-only gate)

- Turn on **"Restrict unsigned URLs"** in ImageKit. Every media URL (video, stream, poster, seek thumbnails) then needs a valid signature, so blocking a signature blocks the media.
- **`POST /api/sign`** (a Next.js route handler) is the player's `signerFn`. It:
  - accepts only URLs under `https://ik.imagekit.io/uequzrrfb/`;
  - maps the path back to a `videos` row;
  - refuses unpublished videos unless the requester is the creator;
  - refuses members-only videos unless the requester is a member or the creator;
  - signs with a short expiry.
  - The ImageKit private key stays on the server only.
- **Grid thumbnails and posters** are signed by the server while the page renders, with a longer expiry rounded to a fixed window so browsers can cache them.
- **Metadata is public, media is gated.** Members-only videos appear in the feed with a lock badge, but only members can play them.

## Database (Supabase)

| Table | Columns |
|---|---|
| `profiles` | `id` → auth.users, `channel_name`, `avatar_url`, `is_creator` |
| `members` | `user_id` → auth.users (a row means the user is a member) |
| `videos` | `id`, `owner_id`, `title`, `description`, `ik_file_id`, `ik_file_path`, `duration_s`, `width`, `height`, `thumb_time_s`, `published` (bool), `published_at`, `members_only` (bool), `created_at` |
| `playlists` | `id`, `owner_id`, `title`, `description`, `created_at` |
| `playlist_items` | `playlist_id`, `video_id`, `position` |

Access rules (row-level security):
- Anyone can read published videos, playlists, playlist items and creator profiles.
- Creators have full access to their own rows.
- Members can read their own membership row.

## ImageKit URLs we rely on (no processing on our side)

- **Stream:** the player builds it from `src` plus `abs`.
- **Thumbnail frame:** `<file>/ik-thumbnail.jpg?tr=so-<seconds>,w-<w>`.
- **Poster:** the same thumbnail URL at the stored `thumb_time_s`.
- **Seek previews and chapters:** handled by the player.

## Milestones

Each milestone ends with a check you run yourself. Nothing moves on until that check passes.

### M0: Foundation
> Lessons from the first attempt, which was deleted on 2026-09-29:
> - `create-next-app` installs Next.js 16 and React 19. The player declares a peer dependency on React ≤18, so add an npm `overrides` entry that points it at the app's React.
> - In Next 16, `middleware` is now called `proxy`. Check `node_modules/next/dist/docs/` before relying on any API.
- Replace the Vite test with Next.js (App Router, TypeScript, Tailwind) in this folder.
- Add `@supabase/ssr`, `@imagekit/next` and `@imagekit/video-player@1.0.0-beta.5`.
- Add `.env.local` with the Supabase URL and anon key, the ImageKit public and private keys, and the URL endpoint.
- Build the dark theme tokens and the app shell (top bar, layout for viewer and studio).
- **Verify:** `npm run dev` shows the dark shell, and `npm run build` passes.

### M3: Studio upload
- Drag-and-drop area that accepts several files, with a progress bar per file.
- Files go **straight from the browser to ImageKit** via `@imagekit/next` `upload()` with `onProgress`, using auth params from `/api/imagekit/auth` (creators only).
- The browser reads duration and dimensions from the local file before uploading. On success we insert a draft `videos` row.
- **Verify:**
  - Uploading 2–3 files shows separate progress bars.
  - The files appear in the ImageKit media library.
  - The draft rows exist.
  - The upload endpoint refuses non-creators.

### M4: Studio video management

- An edit page for title and description.
- A **thumbnail frame picker**: a strip of `ik-thumbnail` frames plus a fine-adjust slider, which saves `thumb_time_s`.
- One-click publish/unpublish and a members-only toggle.
- **Verify:** edits persist, the picked frame becomes the poster, and the publish and members-only toggles update immediately.

### M5: Studio playlists

### M6: Viewer home feed

## Defaults I've assumed (change any of them)

1. **Membership is granted by adding a row in the Supabase dashboard.** There's no member-management UI, because it wasn't on the list.
2. **Creators are users with `is_creator = true`, set in the dashboard.** There's no public creator sign-up.
3. **Members-only videos appear in the feed with a lock badge.** They aren't hidden.
4. **Chapters use ImageKit's AI** (`chapters: true`). This may use ImageKit extension credits.
5. **Sign-in uses email magic links through Supabase Auth.**
